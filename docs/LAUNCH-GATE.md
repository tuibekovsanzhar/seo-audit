# Launch gate: everything that is not verified yet

This is the single list of every item flagged across the seven check categories while this
implementation was built. **Nothing here has been confirmed against the real world.** Each item
says what is unverified, what happens if the assumption is wrong, and how to close it.

Two rules that were followed throughout, and should keep being followed:

1. **An unverified assumption is never allowed to look like a result.** Where an assumption could
   turn into a silent pass, the code reports *Not assessed* with the reason instead. The launch
   gate exists for the cases where that is not enough.
2. **Some gates are enforced in code, not just written down.** Those are marked *code-enforced*
   below; they will refuse to run rather than produce an unverified number.

Status values: **OPEN** (not started), **VERIFIED** (checked against the real source; any residue
noted), **BY DESIGN** (a documented v1 limitation, not a defect).

### What the live runs found (all fixed, each with a regression test)

| Defect | Check | Why it mattered |
|---|---|---|
| `www.<user>.github.io` reported as an invalid certificate | IDX-2 | False S1. A wildcard cannot cover a two-label subdomain, and nobody types that host: the www variant only means something for a registrable domain (`urls.is_registrable_domain`, which knows `com.tr` and `co.uk` as well as `github.io`). |
| "No HTTP→HTTPS redirect" after testing the origin root | IDX-2 | False S4 on any site published under a subdirectory. The check now uses the audited path, and then found the redirect that was there. |
| Politeness violation that never happened | INT-4 | The gate added a monotonic duration to a wall-clock start; a clock adjustment mid-crawl made a correct 2000 ms gap read as 1380 ms. Requests now carry monotonic stamps. |
| "Volkswagen" reported as a brand-name variant | STR-5 | False S4 on Maya's own homepage: the first image whose class mentions "logo" was a customer logo from a "trusted by" strip. Only a single header/nav logo counts now. |
| Footer legal name read as "Maya AI Back to top Built for what's next" | STR-5 | Same false S4: the © line was read out of the whole footer as one string instead of its own text node. |

Historical check on 2026-09-16: `https://withmaya.ai/maya-audit-bot` returned 404, and the local
draft still carried its publishing marker. That was the source of the old startup error. In the
current build, the target website is allowed automatically and the bot info page is optional. If a
page is configured but returns 404, the report records the note and continues auditing the target.
Publishing a Maya-controlled page is still recommended so site owners can identify and contact the
crawler operator. Instructions are in [`../site/maya-audit-bot/PUBLISH.md`](../site/maya-audit-bot/PUBLISH.md).

When reviewing a run, read INT-1 first to see whether the site returned readable pages, then INT-2
for how much was crawled, and INT-4 for robots rules and request pacing. Maya never bypasses login,
robots.txt blocks, rate limits, or other access controls.
